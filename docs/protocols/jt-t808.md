# JT/T 808 道路运输车辆卫星定位系统

> 摘自《JT/T 808-2019 道路运输车辆卫星定位系统 终端通信协议与数据格式》。
> 这份文档是这套协议在 WorkHub 里的标准说明书，界面上「协议文档」看到的就是它；
> 解析器 `jt-t808` 的行为与本文一一对应。

## 1. 接入参数

| 项 | 值 |
| --- | --- |
| 传输 | TCP |
| 方向 | **终端连平台**（终端是客户端），平台这边选「监听」 |
| 端口 | 7612（常用，也有用 10080、20000 等，按现场约定） |
| 编码 | 正文里的中文按 **GBK** |

一台终端一条 TCP 连接。所以「哪条连接」就是「哪个终端」——
注册消息里的终端编号只是补个名字，不是连接的身份。

> 也有反过来做的：平台当客户端主动连终端（少数车载机是这样）。
> 那就在接入方式里选「连接」，填终端的地址。

## 2. 帧结构

一帧按字节排开是这样：

```
0x7E │ 消息体属性(2) │ 序列号(2) │ 消息ID(4) │ 数据长度(4) │ 消息体(n) │ 校验码(1) │ 0x7E
帧标志 │              │            │           │            │            │          │ 帧标志
```

| 段 | 长度 | 说明 |
| --- | --- | --- |
| 帧标志 | 1 字节 | 固定 `0x7E`，包头包尾各一个。 |
| 消息体属性 | 2 字节 | bit0~9 = 消息体长度；bit13 = 加密；bit14 = 分包；其余保留为 0。 |
| 序列号 | 2 字节 | 每包递增，0-65535 循环。**应答的序列号要跟被应答的那一帧对上。** |
| 消息 ID | 4 字节 | 这条消息讲什么，见第 5 节。 |
| 数据长度 | 4 字节 | 消息体长度（不含校验码）。 |
| 消息体 | n 字节 | 正文，格式随消息 ID 而定。 |
| 校验码 | 1 字节 | 从消息体属性到消息体末字节逐字节**异或**。 |

消息体属性与数据长度**说的是同一件事**：属性里的长度是 10 位，数据长度是 32 位。
两个都写，2019 版要求如此。

## 3. 转义

包里出现下面三个字节要转义成两字节，免得跟帧标志撞上：

| 原字节 | 转义后 |
| --- | --- |
| `0x7E` | `0x7D 0x01` |
| `0x7D` | `0x7D 0x02` |
| `0x7F` | `0x7D 0x04` |

`0x7F` 的转义是 2019 版才加的，老设备多半不转——组包时可以关掉。

反解时遇到 `0x7D` 就看下一个字节：`0x01`→`0x7E`、`0x02`→`0x7D`、`0x04`→`0x7F`，
别的照原样。落单的 `0x7D` 不当成转义序列。

> 因为包内的 `0x7E` 都被转义了，**直接找 `0x7E` 当帧边界是安全的**。

## 4. 校验与分包

### 4.1 校验码

- 范围：从**消息体属性**第一个字节到**消息体最后一个字节**（不含校验码本身）；
- 方式：逐字节异或；
- 校验不过的帧照样解，只是标一句「校验码不对」——**不丢帧**，现场数据丢一帧可能就是一条报警。

### 4.2 分包

消息体属性的 bit14 为 1 表示这条消息被拆成了几包，**每包都是完整的一帧**，
消息体的前 4 个字节多带了两个数：

```
包序号(2) │ 总包数(2) │ 本包数据(n)
```

收齐了才拼成一条完整消息。记录里看到的是**拼好的整条**，不是分包本身。

## 6. 网络注册：谁来回什么

平台这一侧要做的不是「收着就行」，而是**有问必答**：

| 终端发来 | 平台回 | 回包正文 |
| --- | --- | --- |
| `0x0001` 终端注册 | `0x8001` 平台注册应答 | 应答序列号(2) + 应答标志(1)，可选失败原因(1)、鉴权码(16) |
| `0x0005` 终端补注册 | `0x8005` 平台补注册应答 | 同上 |
| `0x0002` 终端心跳 | `0x8002` 平台心跳应答 | 空 |

**回包的序列号要跟终端那一帧的序列号一样**，终端对不上就不认。

> 不回会怎样：终端会一直重发注册；心跳收不到应答，终端会以为平台挂了。
> 所以自动应答不是「锦上添花」，是协议的一部分。

应答标志 `0` = 成功，`1` = 失败（后面跟一个失败原因码）。
鉴权码是 2019 版新增的 16 字节，不填就说明平台不做加密。

## 7. 消息体格式

### 7.1 终端注册 `0x0001` / 补注册 `0x0005`

| 字段 | 长度 | 编码 |
| --- | --- | --- |
| 省份编码 | 2 字节 | BCD |
| 市域编码 | 2 字节 | BCD |
| 制造商编码 | 11 字节 | ASCII |
| 终端型号 | 30 字节 | ASCII |
| 终端编号 | 15 字节 | ASCII（通常是 IMEI） |
| 固件版本号 | 20 字节 | ASCII |
| 终端 SIM 卡号 | 20 字节 | BCD |
| 终端认证类型 | 1 字节 | 2019 版新增（补注册没有这一项） |

定长字段尾部用空格或 NUL 补齐。

### 7.2 位置信息 `0x0200` / 补报 `0x0201`

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 标志 | 1 字节 | |
| 经度 | 4 字节 | 有符号，单位 1e-6 度 |
| 纬度 | 4 字节 | 有符号，单位 1e-6 度 |
| 高度 | 2 字节 | 有符号，单位 0.1 米 |
| 速度 | 2 字节 | 单位 0.1 千米/小时（低 12 位是速度，高 4 位是定位速度状态） |
| 方向 | 2 字节 | 0-360 度，`0xFFFF` = 未知 |
| 定位时间 | 6 字节 | BCD，`YYMMDDHHmmss` |
| 卫星数 | 1 字节 | |
| 定位状态 | 1 字节 | bit0 定位有效、bit1 北/南纬、bit2 东/西经 |

经纬度是**有符号**的：南纬西经是负数，别按无符号读。

### 7.3 车辆状态信息 `0x0300`

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 车辆状态 | 1 字节 | 8 个状态位：紧急报警、超速报警、疲劳驾驶、危险信号、GNSS 模块故障、GNSS 天线未接、GNSS 天线短路、终端蓄电池欠压 |
| 扩展车辆状态 | 1 字节 | 8 个状态位：补充电状态、主电源状态、燃油液位低、油路异常，后 4 位标准里是保留 |

### 7.4 通用应答 `0x0004` / `0x8004`

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 应答序列号 | 2 字节 | 被应答消息的序列号 |
| 应答消息 ID | 2 字节 | 被应答的是哪条消息 |
| 结果 | 1 字节 | 0 成功 1 失败 |
| 失败原因 | 1 字节 | 仅失败时存在 |

### 7.5 平台注册应答 `0x8001` / `0x8005`

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 应答序列号 | 2 字节 | 终端注册那一帧的序列号 |
| 应答标志 | 1 字节 | 0 成功 1 失败 |
| 失败原因 | 1 字节 | 仅失败时存在 |
| 鉴权码 | 16 字节 | 2019 版可选 |

### 7.6 文本信息下发 `0x8101`

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 标志 | 1 字节 | |
| 文本信息 | 变长 | GBK |

### 7.7 车辆控制命令 `0x8100`

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 指令字 | 1 字节 | 指令编号 |
| 指令参数 | 变长 | 长什么样由指令字说了算 |

### 7.8 远程设置参数 `0x8104`

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 参数标识 | 4 字节 | 参数 ID |
| 数据体 | 变长 | 参数的值，长度依参数而定 |

## 8. 平台能组哪些包

「组包」是把「要发什么」按协议规则组装成字节帧发出去。
表单是照着协议给的清单渲染的，能组什么、每条要填哪些参数，界面不自己猜。

组包面板里挑的是**协议里的哪一条消息**——所以每条命令都标着自己的消息 ID。

| 命令 | 消息 ID | 参数 | 说明 |
| --- | --- | --- | --- |
| 平台注册应答 | `0x8001` | 应答序列号、应答标志、失败原因、鉴权码 | 手动回注册（自动应答之外再补一次时用） |
| 平台补注册应答 | `0x8005` | 同注册应答 | 手动回补注册 |
| 平台注销应答 | `0x8003` | 序列号 | 正文为空 |
| 平台心跳应答 | `0x8002` | 序列号 | 正文为空 |
| 平台通用应答 | `0x8004` | 应答序列号、被应答消息 ID、结果、失败原因 | |
| 文本信息下发 | `0x8101` | 文本内容、标志 | 中文按 UTF-8 发出；终端只认 GBK 时用 `hex:` 前缀给字节 |
| 车辆控制命令 | `0x8100` | 指令字、指令参数 | 参数按十六进制填 |
| 远程设置参数 | `0x8104` | 参数标识、参数值 | 参数值按十六进制填 |
| 实时位置查询 | `0x8103` | 序列号 | 正文为空，让终端立刻报一次位置 |
| 查询车载终端设备信息 | `0x8102` | 序列号 | 正文为空 |
| 终端注册状态查询 | `0x8105` | 序列号 | 正文为空 |
| 查询卫星定位状态 | `0x8106` | 序列号 | 正文为空 |
| 查询导航信息 | `0x8107` | 序列号 | 正文为空 |
| 请求终端漫游 | `0x8108` | 序列号 | 正文为空 |
| 请求人工监听车辆 | `0x8109` | 序列号 | 正文为空 |
| 查询车辆信号灯 | `0x8110` | 序列号 | 正文为空 |
| 自定义消息 | 自己填 | 消息 ID、序列号、正文字段 | 上面没列的消息：自己给 ID，正文一行一个字段地定义 |

组出来的帧两头各一个 `0x7E`，校验码算好，转义按 2019 版处理。

### 8.1 字段按字节填

面板上每个字段都标着**类型**和**字节宽度**，填错当场拦下来——不静默截断：

| 类型 | 怎么填 | 宽度 |
| --- | --- | --- |
| `u8` / `u16` / `u32` | 十进制（`0x` 开头也认） | 1 / 2 / 4 字节 |
| `hexU8` / `hexU16` / `hexU32` | 十六进制 | 1 / 2 / 4 字节 |
| `text` | 文本，按 UTF-8 发出 | 限的是**字节数**，不是字数 |
| `hex` | 十六进制字节 | 定长，或标了上限 |

**消息 ID 按十六进制填**。消息 ID 在标准里历来写成 `0x8101`，
按十进制填 `8101` 会被当成 33025（`0x1FA5`）——一个完全合法、
却完全不是那个意思的消息 ID，静默发出去最坏。

### 8.2 发之前先预览

「预览字节」只组不发，把帧按协议结构切成几段摆出来：

```
帧标志     7E
消息体属性 00 02
序列号     00 01
消息 ID    00 00 81 01
数据长度   00 00 00 02
数据体     12 34
校验码     A7
帧标志     7E
```

显示的是**去转义后**的字节：转义是链路上的事，对着协议看只会看糊涂。
逐段核对：消息 ID 对不对、长度填得对不对、校验码算得对不对。

### 8.3 自定义消息

标准里没列的消息也能发：自己给消息 ID，正文**一行一个字段**地定义
（名字、类型、字节宽度、值），服务端照着拼；整段十六进制仍可作兜底。

## 9. 实战要点

1. **先回话再解析**：终端注册和心跳的回包不能等——不回，终端就一直重发。
2. **应答序列号要对上**：平台回包的序列号必须等于终端那一帧的序列号。
3. **一个连接一个终端**：JT/T 808 是终端主动连平台，别指望能靠终端编号区分两条一样的连接。
4. **校验不过不丢帧**：标出来就行，丢帧可能丢的就是报警。
5. **经纬度有符号**：南纬西经是负数。
6. **中文是 GBK**：正文里的中文按 GBK 解，直接按 UTF-8 会乱码。
7. **`0x7F` 的转义看版本**：2019 版要转，老设备多半不转——两端对不上就会一直解不出帧。
