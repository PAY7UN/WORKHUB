# 通达 LED2 生板屏协议

> 摘自《通达LED2协议20240111》。这份文档是这套协议在 WorkHub 里的标准说明书，
> 界面上「协议文档」看到的就是它；解析器 `tongda-led2` 的行为与本文一一对应。

## 1. 串口参数

| 项 | 值 |
| --- | --- |
| 波特率 | 38400 |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验 | 无 |
| 字符编码 | **GBK**（中文一律 GBK，不是 UTF-8） |

## 2. 帧结构

一帧按字节排开是这样：

```
0xBB │ ADDR │ LEN │ CMD │ DATA(n) │ SUML │ SUMH │ 0x55
帧头  │地址  │长度 │命令 │ 数据区   │校验低 │校验高 │帧尾
```

| 段 | 长度 | 说明 |
| --- | --- | --- |
| 帧头 | 1 字节 | 固定 `0xBB`。开头不是它的字节一律当噪声丢掉。 |
| 硬件地址 ADDR | 1 字节 | 谁在说话，见第 4 节。 |
| 长度 LEN | 1 字节 | ADDR 到 SUMH 之间的字节数，即 `5 + 数据长度`。 |
| 命令码 CMD | 1 字节 | 这条消息讲什么，见第 5 节。 |
| 数据区 DATA | n 字节 | 正文，格式随命令码而定；中文一律 GBK。 |
| 校验和 | 2 字节 | 从 ADDR 累加到最后一个数据字节，16 位**小端**存放（低字节在前）。 |
| 帧尾 | 1 字节 | 固定 `0x55`。 |

### 2.1 长帧（LEN = 0）

数据超过 250 字节时 LEN 写 0，真实长度放在数据区头两个字节里：

```
0xBB │ ADDR │ 0x00 │ CMD │ DATA0 │ DATA1 │ DATA(n) │ SUML │ SUMH │ 0x55
```

- `DATA0`/`DATA1`：数据长度，**小端**（低字节在前）；
- 数据正文从第 6 字节开始；
- 总长 = `6 + n + 3`。

### 2.2 校验和

- 范围：从 **ADDR** 累加到**最后一个数据字节**（不含校验和本身）；
- 16 位，取低 16 位；
- 存放：**小端**，低字节在前（`SUML` 在前、`SUMH` 在后）。

> 实测提醒：部分命令（如 `0x03`）的校验和覆盖范围与别的命令并不一致（有的只覆盖正文）。
> 所以切帧时以**帧尾 `0x55`** 为准，校验和对不上只标记、不丢帧——拿校验和当切帧依据会误伤真机数据。

## 3. 帧长速算

| 情形 | 总字节数 |
| --- | --- |
| 普通帧 | `LEN + 2` |
| 长帧 | `6 + 数据长度 + 3` |

最短的一帧是 7 字节：`BB ADDR LEN CMD SUML SUMH 55`（无数据）。

## 4. 硬件地址表

| 地址 | 设备 |
| --- | --- |
| `0x01` | 车外头牌 |
| `0x02` | 车外腰牌 |
| `0x03` | 车外尾牌 |
| `0x04` | 车内屏 |
| `0x10` | GPS 终端 |

> 帧头后紧跟的地址不在表里，多半是数据里撞上来的 `0xBB`，按噪声丢掉。
> 设备偶尔会用文档外的地址：连续 8 次对不上后会自动放宽，不再要求地址可识别。

## 5. 命令码与数据区

| 命令码 | 名称 | 数据区字段 |
| --- | --- | --- |
| `0x01` | 广播线路状态 | 时间、上下行、到离站 |
| `0x02` | 路牌字符 | 线路名、起点站、终点站 |
| `0x03` | 车内屏字符 | 屏幕内容、时间字段（协议标注无效） |
| `0x04` | 车内屏广告 | 宣传用语、显示时间 |
| `0x08` | 屏报站 | 到离站、上下行、报站内容 |
| `0x10` | 路牌字符（中英文） | 线路名、中/英起点站、中/英终点站 |
| `0x11` | 侧牌字符 | 总站点数、站点列表 |
| `0x12` | 首末班时间 | 首班时间、末班时间 |
| `0x13` | 票价数据 | 季节标志、投币价格、刷卡价格 |
| `0x14` | 文本信息 | 条数、文本列表 |
| `0x16` | 行驶证信息 | 人数、人员 N |
| `0x17` | 侧牌字符（中英文） | 总站点数、站点列表 |
| `0xE0` | 屏控制指令 | 语音 |
| `0xE1` | 换乘信息 | 原始数据（文档未给格式） |
| `0xE2` | 客流数据 | 门数、门 N |
| `0xE3` | 查询参数 | 查询设备、参数列表 |
| `0xE4` | 查询参数应答 | 参数列表 |
| `0xE5` | 投诉信息 | 投诉时间、投诉记录 |
| `0xE6` | 广告推送 | 原始数据（文档未给格式） |
| `0xE7` | 线路信息 | 原始数据（文档未给格式） |
| `0xF5` | 报警消息 | 报警、报警内容 |

### 5.1 `0x01` 广播线路状态

| 字段 | 说明 |
| --- | --- |
| 时间 | 分/时/日/星期/月/年，**BCD** 编码 |
| 上下行 | 1 字节，最高位 `1` = 下行 |
| 到离站 | 1 字节，最高位 `1` = 到站，低 7 位是站点序号 |

### 5.2 `0x02` 路牌字符

线路名、起点站、终点站。每一段都是 **1 字节长度 + GBK 文本**。

### 5.3 `0x03` 车内屏字符

- 屏幕内容：GBK 文本；
- 时间字段：2 字节，**协议标注无效**（英文示例尾部是 `0x08` 分隔符，中文示例尾部是 2 字节时间）。

### 5.4 `0x04` 车内屏广告

- 宣传用语：1 字节长度 + GBK 文本；
- 显示时间：1 字节，单位秒。

### 5.5 `0x08` 屏报站

| 字段 | 说明 |
| --- | --- |
| 到离站 | 最高位 `1` = 到站，低 7 位是站点序号 |
| 上下行 | 最高位 `1` = 下行，低 7 位是**总站点数** |
| 报站内容 | GBK 文本 |

### 5.6 `0x10` 路牌字符（中英文）

线路名、中文起点站、英文起点站、中文终点站、英文终点站。每一段都是 1 字节长度 + GBK 文本。

### 5.7 `0x11` 侧牌字符

- 总站点数：1 字节；
- 站点列表：每站 = 1 字节序号 + 1 字节长度 + GBK 站名。

### 5.8 `0x12` 首末班时间

- 首班时间：2 字节，十进制 时/分；
- 末班时间：2 字节，十进制 时/分。

> 这一条的时间是**十进制**，不是 BCD——`0x16` 就是 22 点、`0x1E` 就是 30 分。
> 和 `0x01` 广播线路状态里用 BCD 不一样，别混。

### 5.9 `0x13` 票价数据

| 字段 | 说明 |
| --- | --- |
| 季节标志 | `0x00` 常规 / `0x80` 春节 |
| 投币价格 | 1 字节长度 + GBK 文本 |
| 刷卡价格 | 1 字节长度 + GBK 文本 |

### 5.10 `0x14` 文本信息

- 条数：1 字节；
- 文本列表：每条 = 1 字节编号 + 1 字节长度 + GBK 内容。

### 5.11 `0x16` 行驶证信息

- 人数：1 字节；
- 人员 N：角色 1 字节（`0x01` 司机、`0x02` 售票员/乘务员）+ 工号 / 岗位 / 姓名 / 分公司（各 1 字节长度 + GBK）。

### 5.12 `0x17` 侧牌字符（中英文）

- 总站点数：1 字节；
- 站点列表：每站 = 1 字节序号 + 中文名 + 英文名（各 1 字节长度 + GBK）。

### 5.13 `0xE0` 屏控制指令

- 语音：4 字节控制位，`0` = 开启语音，其余 = 关闭。

### 5.14 `0xE2` 客流数据

| 字段 | 说明 |
| --- | --- |
| 门数 | 4 字节**大端** |
| 门 N | 门号 1 字节 + 上车人数 4 字节**小端** + 下车人数 4 字节**小端** |

> 门数是大端、人数是小端——协议就是这么写的，别按同一种读。

### 5.15 `0xE3` 查询参数

- 查询设备：1 字节硬件地址；
- 参数列表：每项 2 字节**小端**参数 ID（见第 6 节）。

### 5.16 `0xE4` 查询参数应答

- 参数列表：每项 = 2 字节小端参数 ID + 1 字节长度 + 数据。

### 5.17 `0xE5` 投诉信息

- 投诉时间：6 字节 BCD（分/时/日/月/年）；
- 投诉记录：角色 1 字节 + 工号（1 字节长度 + GBK）。

### 5.18 `0xF5` 报警消息

- 报警：1 字节，`0` = 关闭，其余 = 开启；
- 报警内容：1 字节长度 + GBK 文本。

## 7. 实战要点

1. **中文是 GBK**：直接按 UTF-8 解会乱码。
2. **切帧认帧尾**：以 `0x55` 收帧，校验和只做标记，不要因为校验失败就丢帧。
3. **长度两种形态**：`LEN > 0` 是普通帧，`LEN = 0` 是长帧，数据长度在 `DATA0/DATA1`（小端）。
4. **大小端混着用**：校验和小端、门数大端、人数小端、参数 ID 小端。
5. **文档没给格式的命令**（`0xE1` 换乘、`0xE6` 广告推送、`0xE7` 线路信息）：只把原始字节带出来，不硬猜。
