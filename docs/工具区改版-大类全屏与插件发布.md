# 工具区改版：大类 → 全屏 + 解析插件发布（初版）

> **历史文档，已作废。** 本文记录的是「两类接入（串口 / 网口）+ 全屏控制台」那一轮的设计。
>
> 现状（2026-11-16）：产品只剩**串口接入**，界面与文案里不再有网口/服务器的说法；
> 原来拆成多页的流程也合并成**一页闭环**，另有「支持的协议」清单页。
> 本文保留作为设计过程记录，其中的「网口接入」「TCP 服务器 / 客户端 / UDP」等说法均已不是现状。

## 一、为什么要改

上一版的毛病不在功能，在**入口**：

- 台账页给的是一个下拉框 + 一个「开一个」按钮。下拉里塞着四种接入方式，
  人得先记住「串口监听 / TCP 服务器 / TCP 客户端 / UDP 收发」这四个词，
  才知道自己要点哪个。
- 点完「开一个」跳到**另一个页面**（`/tools/launch/:kind`），
  在那儿填端口、波特率、协议；再点「开」跳到**第三个页面**（控制台）看数据。
- 三页之间靠「上一步 / 下一步」串着，每一步都得记住前面选了什么。

说白了：**参数和数据被拆到了两个屏幕上**。填参数的时候看不到数据，
看数据的时候看不到参数（控制台上那几行是只读的，改不了）。

## 二、这一版怎么摆

### 2.1 台账页只摆大类

`/tools` 变成两张卡片：

| 大类 | 里面有什么 | 进去之后定什么 |
| --- | --- | --- |
| **串口接入** | 接一根线到本机设备 | 端口、波特率、数据位、停止位、校验、流控 |
| **网口接入** | 在本机开端口收，或主动连出去 | 监听/目标地址、端口 |


大类清单是数据（`shared/tools.ts` 的 `CATEGORY_DEFS`），
以后要加「仿真接入」「蓝牙接入」，加一条记录 + 一种接入方式就行。

### 2.2 点大类 → 全屏，一屏把事办完

```
/tools                 台账：大类卡片 + 正在跑的接入
/tools/serial          全屏：配置态（左上角定参数）
/tools/net             全屏：配置态
/tools/console/:id     全屏：通道态（这条通道的实时数据）
```

全屏页一屏两半：

```
┌─────────────────────────────────────────────────────────┐
│ ← 接入与仿真   网口接入   [TCP 服务器]        [启动]      │
├───────────────────┬─────────────────────────────────────┤
│ 接入方式 [服务器|客户端|UDP]                              │
│ 基本信息          │                                     │
│  监听地址  端口   │        数据实时进这里                 │
│ 协议类型          │                                     │
│  解析插件类型      │                                     │
│ ─────────────     │                                     │
│ 协议详情（帧结构…）│                                     │
└───────────────────┴─────────────────────────────────────┘
```

**左上角**是这一版的核心。三块挨着摆，顺序也是人做事的顺序：

1. **基本信息**——接哪儿、跑多快。
2. **协议类型**——这套字节长什么样。
3. **解析插件类型**——谁来把它读懂。

为什么拆成两个选择：协议和插件真是两件事。
协议是这套线的**规范**（帧头、校验、命令码），插件是**读它的那段代码**。
同一套协议可以有不止一种读法（各家厂商各写一套解析），
所以协议定大方向，插件才是最终那把钥匙。

启动之后跳到通道态（`/tools/console/:id`）：左边是接好了的实况（只读），
右边是这一条通道的实时数据，配置与数据不再分家。

## 三、解析插件：由项目开发者发布

### 3.1 插件是什么

一个目录，装到 `plugins/` 下就能被界面选到：

```
plugins/<插件目录>/
  manifest.json   清单：id、名字、发布者、版本、协议
  index.mjs       实现：导出 createParser() 与 decode(frame)
```

- `createParser()` 决定一帧到哪儿为止（切帧）。
- `decode(frame)` 把一帧读成文本与字段。

详细的字段说明与接口约定见 [`plugins/README.md`](../plugins/README.md)，
可运行的示例见 [`plugins/acme-json-line/`](../plugins/acme-json-line/)。

### 3.2 插件与协议的两种绑定

| 写法 | 含义 | 界面上 |
| --- | --- | --- |
| 写了 `protocol` | 插件自带一套协议 | 多出一种**协议类型**，默认插件就是它 |
| 只写 `protocolId` | 挂在已有协议下 | 协议类型是别人的，**解析插件类型**多一个选项 |

举例：通达 LED2 是内置协议，署「WorkHub 内置」；
某厂家可以发布一个挂在 `tongda-led2` 下的插件——协议类型不变，
解析插件类型里多一个署他们名的选项。

### 3.3 插件坏了不许连累别人

- 清单写错、模块加载失败、该导出的函数没导出 → **只记一条警告**，
  别的插件照常，界面左下角「有插件没装上」把话说清楚。
- 协议 id 撞了、插件 id 撞了 → 同样只记警告，那个插件不装，不覆盖别人的。
- 服务照常起来。

## 四、后端接口的变化

| 接口 | 变化 |
| --- | --- |
| `GET /api/tools` | 多了 `categories`（大类）、`plugins`（插件清单，带发布者与版本）、`pluginWarnings`（装载警告）。`decoders` 字段取消——解码器就是插件的一种 |
| `GET /api/tools/plugins` | 单独取插件清单（目录接口里已带一份） |
| `POST /api/tools/sessions` | 多了 `pluginId`：不传就跟着协议走（用协议自带的默认插件） |

协议类型清单也变了：内置的 + 插件自带的，一并下发。

## 五、这一版没做的

说清楚，免得以为做完了：

- **仿真接入**（设备模拟器、回环、假数据源）：大类清单留了位置，没做。
- **协议类型的新增**：只能由插件自带协议带进来，界面上还不能手建协议。
- **插件的热更新**：插件是启动时读进来的，改了插件要重启服务。
- **通道编排**：一次只能开一条通道，没有「把串口接到网口」这种编排。

### 7.2 跑通的一条真实链路

用仓库自带的示例插件 `acme-json-line`（发布者「ACME 设备组」）走了一遍：

1. `GET /api/tools` 返回三类协议（`raw` / `tongda-led2` / `acme-json-line`）与两个插件
   （`WorkHub 内置` / `ACME 设备组 v1.0.0`）。
2. 在 `/tools/net` 里选「网口接入 → TCP 服务器」，协议选 `acme-json-line`，
   解析插件选「ACME 设备组」，启动后拿到通道地址 `9001`。
3. 客户端发 `{"device":"A1","temp":23.5,"ok":true}`，记录里解出
   `device=A1` / `temp=23.5` / `ok=true`，并标上「插件解析」徽标。

### 7.4 顺手修掉的一个竞态

`manager.test.ts` 里「关掉『记录发出的数据』」这一条，
客户端 `connect` 事件触发时服务端的 `connection` 回调可能还没跑完，
此时往回发会撞上「还没有客户端连进来」。
测试改为**等服务端真的 accept 了再发**（等 `peers` 出现），产品语义没变。
