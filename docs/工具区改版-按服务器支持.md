# 工具区改版：模板 → 服务器实例 → 全屏控制台

> **历史文档，已作废。** 本文记录的是「按服务器支持」那一轮的设计：
> 入口拆成台账页 / 开一个 / 全屏控制台三页，接入方式有串口与网口两类。
>
> 现状（2026-11-16）：产品只剩**串口接入**，界面与文案里不再有网口/服务器的说法；
> 页面也合并成**一页闭环**——参数、实时数据、接收详单、记录与保存同屏，
> 另有「支持的协议」清单页供挑解析插件用。
> 本文保留作为设计过程记录，其中的「服务器实例」「网口接入」等说法均已不是现状。

---

## 0. 确认过的三条决策

| 问题 | 结论 |
|---|---|
| 「按服务器来支持」怎么理解 | **工具是打包发布的，因此谁安装谁就能用**。工具与协议都是代码内置、随安装包走的；不在网页上建「工具条目」 |
| 控制台里能不能换协议 | **启动前选，之后锁定**。换协议等于换一台服务器 |
| 不选协议时算什么 | **算调试记录**：只把字节原样记下来，不做协议解析。仅实现这一档即可 |

## 1. 最终形态

```
/tools                    台账：跑着的服务器 + 内置服务器模板
/tools/launch/:kind       开一个：选协议（可选）+ 选串口/端口 → 启动
/tools/console/:sessionId 全屏控制台：左=这台是谁，中=流量，右=解读
```

**分层**

| 层 | 存哪 | 说明 |
|---|---|---|
| 模板 | 代码内置（`shared/tools.ts`） | 四种接入方式。随安装包发布，装上就能用 |
| 协议 | 代码内置（`BUILTIN_TEMPLATES`） | 两种：「不解析」与「通达 LED2」（具名解码） |
| 实例 | 服务端内存 | 开出来的那台，跑着就一直跑，关页面不断 |
| 记录 | 服务端内存 | 跟实例同生共死 |

**数据库里不再有协议表与工具条目表**（上一轮的 `protocols` / `tool_entries` 已从 schema 里撤掉）。加一种新通道或新协议 = 改代码、重新打包。

## 2. 关键设计点

### 协议是运行时选的，且「不选」是一等公民

`POST /api/tools/sessions` 收 `protocolId`：

- 有值 → 按那套协议切帧、按那套协议读字段；
- 空串 / 不传 → **调试模式**（`raw` 模板）：收到什么算什么，空闲 200ms 切一条。

选了不认识的协议 id 会退回调试模式，而不是让整个服务挂掉。

### 协议决定整屏形态

控制台的布局不随协议变，**内容**随协议变：

| | 具名协议（通达 LED2） | 调试模式（raw） |
|---|---|---|
| 左栏命令码速查 | 有（21 条） | 无 |
| 记录表「内容」列 | 协议摘要 | 十六进制 |
| 右栏字段明细 | 有 | 无（提示「这条没有字段明细」） |

命令码表由解码器自己提供（`NamedDecoder.commands`），经 `/api/tools` 下发——只有一处真相，不用在前端另抄一份。

### 参数优先级

协议推荐值 < 工具默认值 < 人改过的值。

换协议时只填**人没动过**的字段：端口是物理事实，协议是解读方式，换协议不该把串口清掉。

选了通达 LED2，串口参数自动变 38400/8/N/1/none/none；串口本身留空，由人从本机枚举出的 COM 口里挑。

### 全屏

控制台独占整个视口（连应用顶栏都让出来），自己有一条顶栏：返回台账、状态灯、名称、工具徽标、协议徽章、收发字节、条数、发送抽屉、停止。

关掉页面服务器照跑；回来打开同一个 URL 能接上（SSE 续传 + 快照补拉）。

## 4. 已知取舍

- **协议不能中途换**：按确认口径锁死。换协议得重开一台服务器。
- **记录只在内存**：实例停掉记录就没了；要留档得另加落盘。
- **协议模板不可自定义**：想解析新协议 = 写解码器 + 打包发布，不是在网页上加一条。
- **命令码表只对具名解码器有**：只认协议的解码器认识命令码，左栏那块自然空着。

## 5. 第二轮修订：串口、模板改成下拉 + 术语归位

### 5.1 查出来的问题

| 问题 | 根因 | 证据 |
|---|---|---|
| 串口「读不到本机已有的口」 | 前端渲染成了 `<Input list>` + `<datalist>`，datalist 只是输入建议、不是真下拉；列表为空时就是个纯文本框 | `shared/tools.ts` 里该字段本来就声明 `type: 'select'`，与渲染分支不一致——字段声明是对的，渲染是错的 |
| 协议选择占满整屏 | 7 张协议卡片堆叠 | — |
| 串口被说成「服务器 / 实例」 | 台账页把四种接入统一按服务器讲 | — |

另外实测确认：**服务端枚举链路本身是通的**（`GET /api/tools/serial-ports` → `SerialPort.list()`）。开发机上返回空，是因为那台机器真的一个 COM 口都没有（`HKLM\HARDWARE\DEVICEMAP\SERIALCOMM` 不存在、`.NET SerialPort.GetPortNames()` 也为空），属环境问题，不是代码问题。

### 5.2 改动

**串口：真下拉**

- `<select>`，选项来自本机枚举结果，标签带厂商（`COM3 · FTDI`）。
- 列表末尾固定一项「手动输入路径…」→ 切成文本框，兜住虚拟口、设备路径、枚举不到的场合。
- 扫到一个口都没扫到时，直接给文本框 + 一句「本机没扫到串口，可以直接填端口名（如 COM3）」。
- 字段右侧加「重扫」按钮：设备会被拔插，进页面时扫的那一遍很快就不准了。
- 默认选中扫到的第一个口。
- 服务端补了兜底枚举：`SerialPort.list()` 之外，再读 Windows 的 `HARDWARE\DEVICEMAP\SERIALCOMM`，把系统登记在册、但 serialport 没认出来的 COM 口补进来（标「系统登记」）。宁可多列一个打不开的口，也别让人以为本机没串口。

**模板：下拉**

- **接入方式（串口监听 / TCP 服务器 / TCP 客户端 / UDP 收发）的下拉放在台账页**（「开一个接入」区），用 `optgroup` 保留「串口类 / 网口类」分组，选中即显示该方式的说明与当前状态，点「开一个」进配置页。
- **配置页不再给接入方式下拉**：进来是什么就是什么，页面上只留一行「接入方式：串口监听 · 要换接入方式，回台账重新开一个」。
  理由：既然是「开一个串口监听」，屏幕上还挂着一个能选 TCP 的下拉，人只会问「已经是串口了为什么还能选 TCP」——选项本身就在误导。
- 协议下拉**只留两项**：「不解析（调试记录）」与「通达 LED2」。
  删掉的是那批通用定界模板（文本行 / JSON 行 / 十六进制行 / 定长 16 字节 / 长度前缀）——它们谁也不像：真按「定长 16 字节」跑的协议，帧里各字段什么含义还得自己认，套个通用定界只得到一串看不懂的字节，反而更费事。现场说不清就用「不解析」看着原始字节；要认协议就配具名解码器（切帧规则与字段含义一起写清）。
  引擎层的定界能力（分隔符 / 定长 / 长度前缀 / 超时）保留，那是加协议模板时要用的底座。
- 协议选中后下面一行显示协议说明，具名解码器另挂一个徽标——信息一条没丢，但不再刷屏。

**术语：串口不是服务器**

| 原来 | 现在 |
|---|---|
| 运行中的服务器 | 正在跑的接入 |
| 服务器模板 | 接入方式模板 |
| 没有实例在跑 | 串口：「没有在监听」；网口：「没有在跑」 |
| 现在没有服务器在跑 | 现在没有通道在跑 |
| 这台服务器此刻在收什么 | 这条通道此刻在收什么 |

`ToolDef` 新增 `activityLabel` 字段，让每个接入方式自己说自己在跑时该叫什么，不再由界面统一按服务器讲。

### 5.3 验证

`tsc -b` 通过、eslint 0 错、329 项测试全过、`vite build` 通过；浏览器实测：串口下拉列出 `COM3 · FTDI / COM7 · Silicon Labs / COM12（系统登记）`，默认选中第一个；选通达 LED2 波特率自动变 38400 且不清空串口；切到 TCP 服务器端口变 9000、协议保留；选「手动输入路径…」切成文本框。
